\noindent This 24-week program is designed to transform you from a practitioner to a Master Data Engineer on Amazon Web Services (AWS). \section*{Prerequisites \& How to Use This Syllabus}
\begin{itemize}[label=-]
    \item \textbf{Prerequisite skills:} intermediate Python (Boto3), solid SQL, Git workflows (branching, pull requests), Linux/CLI basics, and Docker fundamentals.
    \item \textbf{Weekly cadence:} approximately 10--12 hours per week --- Monday to Wednesday for theory, Thursday for the hands-on project, Friday for the architecture use case.
    \item \textbf{Deliverable expectation:} every capstone must produce a git repository, an architecture diagram, a cost estimate, and a security review checklist, per the Acceptance Criteria boxes that follow each capstone.
    \item \textbf{Assessment:} the 24-week tracking timetable at the end of this document doubles as the assessment checklist --- check off each week only when its project and deliverables are complete.
\end{itemize}

\noindent\textbf{Environment setup checklist:}
\begin{itemize}[label=-]
    \item Install Python 3.x, Git, Docker Desktop, and VS Code.
    \item Install the AWS CLI v2 (plus the Session Manager plugin); verify with \texttt{aws sts get-caller-identity}.
    \item Create an AWS free-tier account with guardrails: MFA on the root user, an IAM Identity Center admin role for daily work, and an AWS Budgets cost alert.
    \item Clone the course repository structure: \texttt{data/}, \texttt{src/}, \texttt{tests/}, \texttt{infra/}, \texttt{docs/}.
    \item Configure credentials via environment variables or named CLI profiles --- never hardcode keys in code or notebooks.
\end{itemize}

\begin{lstlisting}[language=SQL]
-- SCD Type 2 upsert in Redshift: close changed rows, then insert new versions
MERGE INTO dim_customer tgt
USING stg_customer src
  ON tgt.customer_id = src.customer_id AND tgt.is_current = TRUE
WHEN MATCHED AND (tgt.segment <> src.segment OR tgt.city <> src.city)
THEN UPDATE SET valid_to = CURRENT_DATE, is_current = FALSE
WHEN NOT MATCHED
THEN INSERT (customer_id, segment, city, valid_from, valid_to, is_current)
     VALUES (src.customer_id, src.segment, src.city,
             CURRENT_DATE, DATE '9999-12-31', TRUE);

-- second pass: insert the new current versions of the rows just closed
INSERT INTO dim_customer (customer_id, segment, city, valid_from, valid_to, is_current)
SELECT src.customer_id, src.segment, src.city,
       CURRENT_DATE, DATE '9999-12-31', TRUE
FROM stg_customer src
JOIN dim_customer tgt
  ON tgt.customer_id = src.customer_id
 AND tgt.is_current = FALSE
 AND tgt.valid_to = CURRENT_DATE;
\end{lstlisting}

import json, random, time
import boto3

kinesis = boto3.client("kinesis", region_name="us-east-1")
STREAM = "iot-temperature-stream"

def make_reading(sensor_id: int) -> dict:
    return {
        "sensor_id": f"sensor-{sensor_id}",
        "ts": int(time.time()),
        "temp_c": round(random.uniform(15.0, 35.0), 2),
        "battery_pct": random.randint(20, 100),
    }

while True:
    records = []
    for sensor_id in range(1, 51):
        records.append({
            "Data": json.dumps(make_reading(sensor_id)).encode("utf-8"),
            "PartitionKey": f"sensor-{sensor_id}",  # per-sensor ordering
        })
    resp = kinesis.put_records(StreamName=STREAM, Records=records)
    if resp["FailedRecordCount"]:
        # retry only failed records with backoff (ProvisionedThroughputExceeded)
        failed = [r for r, o in zip(records, resp["Records"]) if "ErrorCode" in o]
        time.sleep(0.5)
        kinesis.put_records(StreamName=STREAM, Records=failed)
    time.sleep(1)
\end{lstlisting}

  ad_id STRING, imp_ts TIMESTAMP(3),
  WATERMARK FOR imp_ts AS imp_ts - INTERVAL '10' SECOND
) WITH ('connector' = 'kinesis', 'stream' = 'imps', ...);

CREATE TABLE clicks (
  user_id STRING, ad_id STRING, click_ts TIMESTAMP(3),
  WATERMARK FOR click_ts AS click_ts - INTERVAL '5' SECOND
) WITH ('connector' = 'kinesis', 'stream' = 'clicks', ...);

-- Interval join: attribute clicks to impressions seen up to 15 min prior.
-- Watermarks let Flink drop state older than the join interval.
SELECT i.ad_id, c.user_id, c.click_ts

JOIN clicks c ON i.ad_id = c.ad_id

\prodnote{A naive \texttt{DELETE} does not erase data on AWS: S3 versioning retains prior object versions, Redshift snapshots and automated backups keep deleted rows until they expire, Kinesis records persist for the full retention window, and Glacier archives are immutable until their retention period ends. \section{Appendix A: Glossary}
\begin{description}[leftmargin=3.5cm, style=nextline, itemsep=1pt]
    \item[S3 Storage Class] Durability/cost tier of an S3 object (Standard, IA, Glacier) chosen by access pattern and lifecycle rules.
    \item[Object Lock] S3 write-once-read-many protection preventing deletion or overwrite for a retention period.
    \item[Aurora Serverless v2] Auto-scaling Aurora configuration that adjusts capacity in ACU increments based on load.
    \item[AWS DMS] Managed service for one-time migrations and continuous CDC replication between database engines.
    \item[CDC] Change Data Capture --- streaming inserts, updates, and deletes from source transaction logs to targets.
    \item[RCU/WCU] DynamoDB Read/Write Capacity Units; the billing and throughput model for provisioned tables.
    \item[GSI] Global Secondary Index --- an alternate query key structure on a DynamoDB table with its own throughput.
    \item[RA3 node] Redshift node type with managed storage, decoupling compute from data volume.
    \item[Distribution Style] Redshift rule (EVEN, KEY, ALL, AUTO) governing how rows are spread across compute slices.
    \item[Redshift Spectrum] Redshift feature querying exabytes of S3 data in place via the Glue Data Catalog.
    \item[Glue Data Catalog] Central Hive-metastore-compatible metadata store shared by Athena, Redshift, EMR, and Glue.
    \item[Lake Formation] Governance layer enforcing database/table/column permissions over S3 data lake objects.
    \item[LF-Tag] Key-value attribute in Lake Formation enabling tag-based access control instead of named grants.
    \item[DPU] Data Processing Unit --- Glue's compute billing unit (4 vCPU, 16 GB) allocated per job.
    \item[Job Bookmark] Glue mechanism tracking processed data so re-runs handle only new or changed partitions.
    \item[MWAA] Managed Workflows for Apache Airflow --- AWS-hosted Airflow with autoscaling workers.
    \item[Kinesis Shard] Fixed-throughput unit of a Kinesis stream (1 MB/s in, 2 MB/s out); partition keys map to shards.
    \item[Iterator Age] Kinesis consumer lag metric; rising values signal the consumer is falling behind retention.
    \item[Watermark] Flink event-time threshold declaring how long late events are accepted into a window.
    \item[SPICE] QuickSight's in-memory calculation engine for fast dashboard queries.
    \item[Feature Store] SageMaker repository for versioned ML features with online (low-latency) and offline (S3) stores.
    \item[Model Registry] SageMaker catalog of versioned, approved model artifacts with deployment lineage.
    \item[Model Monitor] SageMaker service detecting data-quality and drift violations on production endpoints.
    \item[Macie] ML-driven service discovering and classifying PII and sensitive data in S3.
    \item[VPC Endpoint] Private network path to AWS services (Gateway for S3/DynamoDB, Interface via PrivateLink) avoiding the public internet.
\end{description}

\section{Appendix F: Portfolio \& Presentation Guide}
Each capstone should ship as a public GitHub repository you can walk an interviewer through.

\noindent\textbf{README structure (in this order):}
\begin{enumerate}[itemsep=1pt]
    \item \textbf{Problem:} one paragraph --- who hurts, at what scale, and what ``done'' means.
    \item \textbf{Architecture diagram first:} reviewers decide in 10 seconds; lead with the picture.
    \item \textbf{Setup:} exact commands to reproduce from a clean environment (prereqs, IaC, seed data).
    \item \textbf{Screenshots:} working dashboard, pipeline run, and one alarm firing.
    \item \textbf{Cost estimate:} monthly table with the two optimization decisions you made.
    \item \textbf{Lessons learned:} one failure you hit and how you fixed it.
\end{enumerate}

\noindent\textbf{Resume bullet templates (two per milestone --- fill in the brackets):}
\begin{itemize}[label=-, itemsep=1pt]
    \item \textbf{M1:} Built a multi-tier e-commerce data backend on Aurora Serverless, DynamoDB, and S3 with DMS CDC replication, reconciling [N] rows/day with automated data-quality tests.
    \item \textbf{M1:} Designed multi-region S3 lifecycle and DR strategy, cutting projected storage spend [X]\% via Glacier transitions and validated restores.
    \item \textbf{M2:} Built a governed lakehouse (S3/Parquet, Glue Catalog, Lake Formation column-level security) serving Redshift Spectrum dashboards to [N] analysts.
    \item \textbf{M2:} Benchmarked Athena vs.\ Spectrum vs.\ Redshift Serverless, documenting a cost decision saving $\sim$\$[X]/month at [N] TB scanned.
    \item \textbf{M3:} Automated a batch ELT pipeline with EventBridge and Step Functions orchestrating Glue data-quality gates and EMR Serverless Spark into Redshift.
    \item \textbf{M3:} Authored MWAA (Airflow) DAGs with idempotent Glue bookmarks and SNS runbook alerting, eliminating duplicate loads on re-runs.
    \item \textbf{M4:} Built a real-time fraud-detection stream (Kinesis $\rightarrow$ Flink sliding windows $\rightarrow$ Redshift $\rightarrow$ QuickSight) flagging cross-city card use within 10 minutes.
    \item \textbf{M4:} Implemented idempotent Kinesis consumers with DLQ routing, sustaining [N] events/minute with zero duplicate alerts.
    \item \textbf{M5:} Productionized an MLOps pipeline: Athena feature extraction $\rightarrow$ SageMaker Feature Store $\rightarrow$ Pipelines $\rightarrow$ Model Registry with Model Monitor drift alarms.
    \item \textbf{M5:} Gated auto-retraining behind metric thresholds and human approval, catching [N] injected drift violations before deployment.
    \item \textbf{M6:} Deployed a three-account governed data mesh with Lake Formation LF-Tags, Macie tokenization quarantine, and VPC endpoint lockdown via Terraform.
    \item \textbf{M6:} Built GitHub Actions CI/CD with OIDC federation and dbt tests gating Dev$\rightarrow$Prod promotion for [N] data models.
\end{itemize}

\noindent\textbf{Talking about your project in interviews:} open with the problem and its scale (``10M rows nightly, 500 analysts''), then show the architecture diagram and narrate two design decisions with their trade-offs --- interviewers score reasoning, not service names. Have one failure story ready (what broke, how you detected it, what you changed). Close with numbers: cost per month, latency, row counts. If asked ``what would you do differently,'' you pass only if you have a real answer --- write it in the README's lessons-learned section while the project is fresh.
