\section*{Prerequisites \& How to Use This Syllabus}
\begin{itemize}[label=-]
    \item \textbf{Prerequisite skills:} working knowledge of Python and SQL, Git fundamentals (clone/branch/commit/PR), Windows/Linux command-line basics, Docker fundamentals (images, containers, registries), and a free Azure subscription.
    \item \textbf{Weekly cadence:} $\sim$10--12 hours per week. Monday--Wednesday cover theory, Thursday is a hands-on project, Friday is an architecture use case.
    \item \textbf{Deliverable expectation:} every monthly capstone must produce a git repository, an architecture diagram, a monthly cost estimate, and a security review checklist, per the Acceptance Criteria boxes after each capstone.
    \item \textbf{Self-assessment:} the 24-week tracking timetable at the end doubles as your assessment checklist --- check off a week only when its project or capstone is complete and documented. Each week also ends with a Self-check; answers are in Appendix D.
\end{itemize}

\subsection*{Milestone 1 Capstone: Reference Solution Sketch}
\begin{itemize}[label=-, itemsep=1pt]
    \item \textbf{Architecture (one line):} Azure SQL Serverless for billing + Cosmos DB (Session consistency, partitioned by \texttt{/customerId}) for carts/clickstream + ADLS Gen2 for images/archives, with Change Feed $\rightarrow$ ADLS event propagation --- each tier matched to its access pattern instead of one store forced to do everything.
    \item \textbf{Steps, in order:} (1) provision all services via Bicep/CLI with Managed Identities; (2) model the cart container around \texttt{/customerId}; (3) enable Change Feed and deploy the processor; (4) land events append-only in ADLS; (5) add diagnostic settings and cost alerts; (6) write README + diagram.
    \item Hardest part --- a minimal Change Feed processor that is safe under replay:
\begin{lstlisting}[language=Python]
from azure.cosmos import CosmosClient
from azure.identity import DefaultAzureCredential

def handle_changes(changes):
    for doc in changes:
        path = f"clickstream/{doc['customerId']}/{doc['id']}.json"
        adls.upload(path, json.dumps(doc), overwrite=True)  # idempotent

container = CosmosClient(URL, DefaultAzureCredential()) \
    .get_container_client("shop", "carts")
for change in container.query_items_change_feed(is_start_from_beginning=True):
    handle_changes([change])
\end{lstlisting}
    \item \textbf{Pitfall:} a skewed partition key (one whale customer) creates a hot partition and 429 throttling --- pick high-cardinality keys.
    \item \textbf{Pitfall:} overwriting on Change Feed re-delivery corrupts state unless the sink write is idempotent (same \texttt{id} $\rightarrow$ same blob).
    \item \textbf{Pitfall:} leaving storage public-access enabled --- disable it and use Managed Identity from day one.
\end{itemize}

\begin{lstlisting}[language=SQL]
-- SCD Type 2 upsert on a Synapse Dedicated SQL Pool
MERGE INTO dim_customer AS tgt
USING stg_customer AS src
    ON tgt.customer_id = src.customer_id AND tgt.is_current = 1
WHEN MATCHED AND (tgt.email <> src.email OR tgt.city <> src.city) THEN
    UPDATE SET tgt.valid_to = CAST(GETDATE() AS date), tgt.is_current = 0
WHEN NOT MATCHED THEN
    INSERT (customer_id, email, city, valid_from, valid_to, is_current)
    VALUES (src.customer_id, src.email, src.city,
            CAST(GETDATE() AS date), '9999-12-31', 1);

-- insert new versions for the rows just closed by the MERGE
INSERT INTO dim_customer (customer_id, email, city, valid_from, valid_to, is_current)
SELECT src.customer_id, src.email, src.city,
       CAST(GETDATE() AS date), '9999-12-31', 1
FROM stg_customer AS src
JOIN dim_customer AS tgt
    ON tgt.customer_id = src.customer_id AND tgt.is_current = 1
WHERE tgt.email <> src.email OR tgt.city <> src.city;
\end{lstlisting}

\subsection*{Milestone 2 Capstone: Reference Solution Sketch}
\begin{itemize}[label=-, itemsep=1pt]
    \item \textbf{Architecture (one line):} ADLS Gen2 bronze/silver/gold in Delta Lake format, transformed with Databricks, served as Synapse Serverless SQL views to Power BI, cataloged by Purview --- serverless serving avoids paying for an idle dedicated warehouse.
    \item \textbf{Steps, in order:} (1) land raw retail files in bronze; (2) clean/dedupe into silver Delta tables; (3) model gold as a star schema (grain declared first, SCD2 customers); (4) run \texttt{OPTIMIZE} + \texttt{VACUUM} on Delta tables; (5) register and scan in Purview with PII classifications; (6) expose gold via serverless views; (7) connect Power BI with DirectQuery.

from azure.eventhub import EventData

SELECT card_id, COUNT(*) AS swipes,
       COUNT(DISTINCT city) AS cities
INTO fraud_alerts
FROM card_swipes TIMESTAMP BY event_ts
GROUP BY card_id, SlidingWindow(minute, 10)
HAVING COUNT(DISTINCT city) > 1
\end{lstlisting}

    \item \textbf{Architecture (one line):} three subscriptions --- A ingests and tokenizes PII (Event Hubs + Functions + Key Vault), B hosts Synapse/ADLS analytics, C runs Purview governance --- peered VNets with Private Endpoints everywhere and zero public network access, all deployed by Terraform/Bicep modules.
    \item \textbf{Steps, in order:} (1) write a Terraform module per subscription with an Azure Storage state backend; (2) peer VNets and create private DNS zones; (3) deploy the tokenization Function with Key Vault references; (4) deploy Synapse with public access disabled; (5) register sources in Purview and scan; (6) gate the tokenized load with dbt tests in GitHub Actions; (7) prove zero public reachability from outside the VNets.

  private_dns_zone_group {
    private_dns_zone_ids = [azurerm_private_dns_zone.dfs.id]
  }
}
\end{lstlisting}
    \item \textbf{Pitfall:} creating the Private Endpoint but not the DNS zone --- name resolution still returns the public IP and traffic fails or leaks.
    \item \textbf{Pitfall:} \texttt{public\_network\_access\_enabled} defaults to true on several resources --- set it to false explicitly in code.
    \item \textbf{Pitfall:} cross-subscription RBAC sprawl --- centralize role assignments in the governance subscription and audit them monthly.
\end{itemize}

\section{Appendix A: Glossary}
\begin{description}[leftmargin=3.5cm, style=nextline]
    \item[ADLS Gen2] Azure Data Lake Storage Gen2 --- Blob Storage with a hierarchical namespace for analytics.
    \item[ADF] Azure Data Factory --- managed ETL/ELT orchestration service with pipelines and Mapping Data Flows.
    \item[ASA] Azure Stream Analytics --- serverless real-time event processing with a SQL-like query language.
    \item[Bicep] Azure-native declarative Infrastructure-as-Code language that transpiles to ARM templates.
    \item[CDC] Change Data Capture --- streaming of insert/update/delete changes from a source database.
    \item[CETAS] CREATE EXTERNAL TABLE AS SELECT --- serverless SQL pattern to materialize query results to the lake.
    \item[Cosmos DB] Globally distributed multi-model NoSQL database billed in Request Units.
    \item[cDWU] Compute Data Warehouse Unit --- the compute sizing metric of Synapse Dedicated SQL Pools.
    \item[dbt] SQL-based transformation framework with models, tests, and documentation as code.
    \item[Delta Lake] Open table format adding ACID transactions and time travel to data lakes.
    \item[DMS] Azure Database Migration Service --- orchestrates schema and data migration with optional CDC.
    \item[DP-700] Implementing Data Engineering Solutions Using Microsoft Fabric --- the Azure data engineering certification succeeding DP-203.
    \item[Event Hubs Capture] Automatic batched delivery of Event Hubs streams to ADLS Gen2 or Blob Storage.
    \item[Integration Runtime] The ADF compute used to execute activities (Azure, Self-Hosted, or Azure-SSIS).
    \item[Key Vault] Managed store for secrets, keys, and certificates with rotation and access policies.
    \item[Lakehouse] Architecture combining data lake storage with warehouse-style ACID tables (Delta Lake).
    \item[Managed Identity] Entra ID identity managed by Azure, eliminating stored credentials in code.
    \item[Mapping Data Flow] ADF's visual, code-free transformation engine executed on managed Spark.
    \item[Private Endpoint] Network interface giving a resource a private IP inside your VNet.
    \item[Purview] Microsoft's unified data governance, catalog, lineage, and classification service.
    \item[Request Unit (RU)] Cosmos DB throughput currency; every operation consumes RUs.
    \item[Structured Streaming] Spark's micro-batch/continuous stream processing API over DataFrames.
    \item[Synapse Analytics] Azure's analytics service unifying Dedicated/Serverless SQL pools and Spark.
    \item[Terraform azurerm] HashiCorp provider for provisioning Azure resources declaratively.
    \item[Watermark] Stream-processing tolerance defining how long late events are still accepted.
\end{description}

\noindent\textbf{Week 2:}
\begin{enumerate}[itemsep=0pt]
    \item vCore --- you pick hardware, cores, and storage directly; DTU is a bundled unit.
    \item Managed, automatic failover of a group of databases to another region.
    \item Avoids overwriting the live database; allows verification before cutover.
    \item It auto-pauses when idle, billing only storage during downtime.
    \item Geo-replication is an async DR secondary; read scale-out serves reads in-region.
\end{enumerate}
\noindent\textbf{Week 3:}
\begin{enumerate}[itemsep=0pt]
    \item RU prices every operation; cross-partition fan-out multiplies RU consumption.
    \item Strong consistency.
    \item Per-session read-your-writes without strong-consistency latency and cost.
    \item Ordered changes within a partition key; no cross-partition ordering.
    \item Skewed keys create hot partitions that throttle; even keys spread RU load.

\begin{enumerate}[itemsep=0pt]

    \item Centralized throttling, authentication, quotas, and monitoring for ingestion APIs.
    \item They go stale; set TTLs or explicit invalidation on writes.

\end{enumerate}

\begin{enumerate}[itemsep=0pt]
