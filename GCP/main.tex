\section*{Prerequisites \& How to Use This Syllabus}
\begin{itemize}[label=-]
    \item \textbf{Prerequisite skills:} intermediate Python, solid SQL, Git fundamentals, Linux/CLI basics, and Docker fundamentals. You also need a Google Cloud project with billing enabled (free trial credits are sufficient for most labs).
    \item \textbf{Weekly cadence:} plan for roughly 10--12 hours per week --- Monday to Wednesday for theory and service deep dives, Thursday for the hands-on project, and Friday for the architecture use case.
    \item \textbf{Deliverable expectation:} every capstone must produce a git repository, an architecture diagram, a monthly cost estimate, and a security review checklist, per the Acceptance Criteria boxes in each milestone.
    \item \textbf{Assessment:} the 24-week tracking timetable at the end of this document doubles as your assessment checklist --- mark a week complete only when its deliverables are committed.
    \item \textbf{Self-checks:} every week ends with 5 self-check questions; answer them from memory before consulting the answer key in Appendix D.
\end{itemize}

\noindent\textbf{Environment setup checklist} (complete before Week 1):
\begin{itemize}[label=$\square$]
    \item Install Python 3.x, Git, Docker Desktop, and VS Code (with the Python and Cloud Code extensions).
    \item Install the \texttt{gcloud} CLI and \texttt{bq} (bundled), plus Terraform for Week 24.
    \item Create a Google Cloud free-tier project with billing enabled and \$300 trial credits.
    \item Clone a course repository structured as \texttt{data/}, \texttt{src/}, \texttt{tests/}, \texttt{infra/}, \texttt{docs/}.
    \item Configure credentials via environment variables and Application Default Credentials (\texttt{gcloud auth application-default login}) --- never hardcode keys in source.
\end{itemize}

\subsection*{Milestone 1 Capstone: Reference Solution Sketch}
\begin{itemize}[label=-, leftmargin=1.5em]
    \item \textbf{Architecture:} Cloud SQL (users) + Spanner (inventory/checkout, multi-region) + Bigtable (clickstream) + GCS (product images), all on private IPs inside one VPC --- each store matched to its workload profile, nothing over-provisioned.
    \item \textbf{Steps:} (1) provision all four stores via Terraform/gcloud scripts; (2) load the Olist dataset with seeded generators; (3) configure private IP and authorized networks; (4) run the failover, Spanner consistency, and Bigtable hotspot tests; (5) export Cloud Monitoring dashboards; (6) write the cost estimate.
    \item \textbf{Hardest part --- a hotspot-free Bigtable row key:}
\begin{lstlisting}[language=Python]
import hashlib
def click_row_key(user_id: str, event_ts: int) -> str:
    # salt spreads writes across tablets; reversed ts sorts newest first
    salt = hashlib.md5(user_id.encode()).hexdigest()[:4]
    return f"{salt}#{user_id}#{9999999999 - event_ts}"
\end{lstlisting}
    \item \textbf{Pitfall:} monotonically increasing order IDs as Spanner primary keys funnel writes onto one split --- use UUIDs or bit-reversed sequences.
    \item \textbf{Pitfall:} leaving Cloud SQL on its default public IP fails the private-connectivity security review.
    \item \textbf{Pitfall:} reading Bigtable without an App Profile makes single-cluster failover tests meaningless.
\end{itemize}

-- SCD Type 2 upsert into a customer dimension on BigQuery
MERGE analytics.dim_customer T
USING staging.customers_daily S
ON T.customer_id = S.customer_id AND T.is_current = TRUE
WHEN MATCHED AND (T.email <> S.email OR T.segment <> S.segment) THEN
  UPDATE SET valid_to = CURRENT_DATE(), is_current = FALSE
WHEN NOT MATCHED THEN
  INSERT (customer_id, email, segment, valid_from, valid_to, is_current)
  VALUES (S.customer_id, S.email, S.segment, CURRENT_DATE(), DATE '9999-12-31', TRUE);
-- Follow with a second INSERT for the new versions of the matched rows.
\end{lstlisting}

\subsection*{Milestone 2 Capstone: Reference Solution Sketch}
\begin{itemize}[label=-, leftmargin=1.5em]
    \item \textbf{Architecture:} GCS Parquet zones $\rightarrow$ BigLake tables with policy tags and row access policies $\rightarrow$ BigQuery materialized views + BI Engine $\rightarrow$ Analytics Hub listing --- one governed copy serving both internal dashboards and external partners.
    \item \textbf{Steps:} (1) land 5 years of retail Parquet in GCS partitioned by date; (2) create BigLake tables over the files; (3) apply a row access policy on \texttt{region} and a policy tag on customer PII columns; (4) build MVs for executive KPIs and add a BI Engine reservation; (5) publish the curated dataset via Analytics Hub; (6) run the negative security test.
    \item \textbf{Hardest part --- row-level security that survives audits:}
\begin{lstlisting}[language=SQL]
CREATE ROW ACCESS POLICY region_filter
ON lakehouse.fact_sales
GRANT TO ("group:analysts-eu@example.com")
FILTER USING (region = "EU");
-- negative test: query as an analyst-us member must return zero EU rows
\end{lstlisting}
    \item \textbf{Pitfall:} clustering on a low-cardinality column yields no pruning --- cluster on the columns selective filters actually use.
    \item \textbf{Pitfall:} materialized views support a restricted SQL subset (no arbitrary joins or UDFs) --- keep them simple pre-aggregations.
    \item \textbf{Pitfall:} policy tags deny by default; a forgotten group grant blocks dashboards silently --- always pair with a negative test.
\end{itemize}

\subsection*{Milestone 3 Capstone: Reference Solution Sketch}
\begin{itemize}[label=-, leftmargin=1.5em]
    \item \textbf{Architecture:} Cloud Scheduler $\rightarrow$ Composer DAG $\rightarrow$ (Datastream freshness check $\rightarrow$ serverless Dataproc Spark feature job $\rightarrow$ BigQuery load $\rightarrow$ MV refresh) --- one orchestrator, each stage idempotent.
    \item \textbf{Steps:} (1) verify CDC row counts between source and BigQuery; (2) run the Spark aggregation on an ephemeral cluster; (3) load with \texttt{WRITE\_TRUNCATE} on a date partition; (4) refresh the materialized view; (5) wire failure email and latency alerts; (6) document the backfill runbook.
    \item \textbf{Hardest part --- an idempotent Spark write safe under retries:}
\begin{lstlisting}[language=Python]
ds = kwargs["ds"]  # logical date from Airflow context
out = f"gs://ml-features/dt={ds}"  # deterministic path per run
(spark.read.parquet(f"gs://cdc-staging/dt={ds}")
      .groupBy("customer_id")
      .agg(F.count("*").alias("orders_30d"),
           F.sum("amount").alias("spend_30d"))
      .write.mode("overwrite").parquet(out))
# BQ load uses WRITE_TRUNCATE on partition dt=ds: re-runs replace, never duplicate
\end{lstlisting}
    \item \textbf{Pitfall:} \texttt{catchup=True} on a new DAG floods weeks of backfill runs at once --- disable it or cap \texttt{max\_active\_runs}.
    \item \textbf{Pitfall:} append-mode loads double-count rows when a task retries --- always overwrite by partition.
    \item \textbf{Pitfall:} passing DataFrames or file contents through XComs stalls the scheduler --- pass paths and row counts only.
\end{itemize}

import apache_beam as beam
from apache_beam.coders import coders
from apache_beam.transforms.userstate import BagStateSpec, TimerSpec, on_timer

class DedupWithTimer(beam.DoFn):
    SEEN = BagStateSpec("seen", coders.StrUtf8Coder())
    EXPIRY = TimerSpec("expiry")

    def process(self, element, seen=beam.DoFn.StateParam(SEEN),
                expiry=beam.DoFn.TimerParam(EXPIRY)):
        key, event = element
        expiry.set(event["event_ts"] + 600)  # state TTL: 10 min
        if event["event_id"] in set(seen.read()):
            return  # duplicate: discard
        seen.add(event["event_id"])
        yield event

    @on_timer(EXPIRY)
    def on_expiry(self, seen=beam.DoFn.StateParam(SEEN)):
        seen.clear()  # free per-key state at timer fire
\end{lstlisting}

    events

@component(base_image="python:3.10")
def register_gate(evaluation: Input[Metrics]) -> bool:
    auc = evaluation.metadata["roc_auc"]
    if auc < 0.80:
        raise ValueError(f"ROC AUC {auc:.3f} below 0.80 gate")
    return True  # downstream register/deploy tasks only run if this passes
\end{lstlisting}

    \item Architecture diagram committed showing projects, VPC SC perimeter, and governance flows.

\end{itemize}

\subsection*{Milestone 6 Capstone: Reference Solution Sketch}
\begin{itemize}[label=-, leftmargin=1.5em]
    \item \textbf{Architecture:} three projects --- A (ingest + DLP tokenization), B (BigLake analytics), C (Dataplex governance) --- inside one VPC Service Controls perimeter, everything provisioned by Terraform --- blast radius of any single compromise is one project.
    \item \textbf{Steps:} (1) Terraform the three projects and perimeter; (2) stream PII into Project A and tokenize with DLP + Cloud KMS; (3) expose only tokenized tables as BigLake assets in Project B; (4) enforce row-level security and policy tags from Project C; (5) run the negative perimeter test and audit-log alert.
    \item \textbf{Hardest part --- deterministic, key-managed tokenization:}
\begin{lstlisting}[language=Python]
from google.cloud import dlp_v2
dlp = dlp_v2.DlpServiceClient()
crypto = {"crypto_key": {"kms_wrapped": {
            "wrapped_key": wrapped_key_bytes,
            "crypto_key_name": kms_key_resource}},
          "surrogate_info_type": {"name": "USER_TOKEN"}}
# deterministic FFX: same input -> same token, joins still work,
# but detokenization requires an auditable Cloud KMS permission
\end{lstlisting}
    \item \textbf{Pitfall:} the perimeter blocks Composer/Build API calls from outside --- add every CI and orchestration service to the perimeter or an ingress rule.
    \item \textbf{Pitfall:} cross-project Terraform applies race --- order them with explicit \texttt{depends\_on} or separate state per project.
    \item \textbf{Pitfall:} tokenized PII can still be re-identified through quasi-identifiers (zip + birthdate) --- run DLP risk analysis on the "safe" tables.
\end{itemize}

\section{Appendix A: Glossary}
\begin{description}[style=nextline]
    \item[Slot] BigQuery's unit of compute capacity; queries consume slots from on-demand or edition-based reservations.
    \item[BigLake] BigQuery storage engine that exposes GCS files as tables with fine-grained (row/column) security.
    \item[Analytics Hub] BigQuery service for governed data sharing and data clean rooms across organizations.
    \item[BI Engine] In-memory acceleration layer for BigQuery that speeds up dashboard queries.
    \item[Dataflow] Managed runner for Apache Beam batch and streaming pipelines with autoscaling.
    \item[Watermark] Beam's estimate of event-time completeness; data arriving behind it is considered late.
    \item[Allowed Lateness] Windowing parameter controlling how long a window accepts late-arriving events.
    \item[Pub/Sub Dead-Letter Topic] Topic that receives messages a subscription failed to deliver after N attempts.
    \item[Spanner TrueTime] Globally synchronized clock API enabling Spanner's external consistency guarantees.
    \item[Bigtable Row Key] Primary index of a Bigtable table; poor key design causes hotspotting.
    \item[Dataproc] Managed Hadoop/Spark service; supports ephemeral and serverless clusters.
    \item[Datastream] Serverless change data capture (CDC) service replicating database changes into GCS or BigQuery.
    \item[Cloud Composer] Managed Apache Airflow environment (v2 runs on GKE with autoscaling).
    \item[DAG] Directed Acyclic Graph --- an Airflow pipeline definition of tasks and dependencies.
    \item[Dataform] BigQuery-native tool for SQL pipelines: SQLX models, assertions, and scheduled runs.
    \item[SQLX] Dataform's SQL extension adding model configs, dependencies, and assertions to plain SQL.
    \item[Assertion] Declarative data-quality test in Dataform (or dbt) that fails a run when rows violate a condition.
    \item[Dataplex] Governance fabric organizing lakes, zones, and assets with Auto Data Quality and lineage.
    \item[VPC Service Controls] Perimeter-based security that blocks data exfiltration even with valid IAM credentials.
    \item[CMEK] Customer-Managed Encryption Keys in Cloud KMS, giving you key rotation and revocation control.
    \item[DLP InfoType] A category of sensitive data (e.g., email, credit card) detected by Cloud DLP.
    \item[Vertex AI Feature Store] Managed store for ML features with online and offline serving.
    \item[Model Drift] Degradation of model performance when production data diverges from training data.
    \item[LookML] Looker's semantic modeling language defining dimensions, measures, and explores.
\end{description}

\section{Appendix D: Self-Check Answer Key}

\textbf{Week 1:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Archive --- lowest storage price for rarely read data.
    \item Only the storage class (access cost/latency), never the data itself.
    \item Petabyte-scale transfers where bandwidth makes online transfer impractical.
    \item Copy the object's older generation back, e.g.\ \texttt{gs://bucket/object\#generation}.
    \item Deletion, corruption, and regional loss still need replication plus tested recovery.
\end{enumerate}

\textbf{Week 2:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item A synchronous standby in another zone with automatic failover.
    \item PITR replays WAL to a timestamp; in-place restore would destroy current data.
    \item When traffic must stay inside the VPC and off the public internet.
    \item Analytical scans and aggregations over large PostgreSQL datasets.
    \item Continuous CDC replication followed by a short cutover window.
\end{enumerate}

\textbf{Week 3:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Globally agreed commit timestamps, enabling external (strong) consistency.
    \item Monotonic keys concentrate writes on one split, causing hotspots.
    \item Co-locating child rows with parents for fast local joins and cascades.
    \item Synchronous multi-region replication coordinated by TrueTime.
    \item Small or single-region workloads --- Spanner's cost and complexity dominate.
\end{enumerate}

\textbf{Week 4:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Sequential keys funnel writes onto a single tablet server.
    \item Spreads load across tablets; sacrifices efficient range scans.
    \item Routing and replication policy per application.
    \item A heatmap of row-key access that exposes hotspots.
    \item How many versions or how much cell history to retain.
\end{enumerate}

\textbf{Week 5:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Colossus (storage), Jupiter (network), Dremel (compute) scale independently.
    \item Steady, high-utilization workloads needing predictable monthly spend.
    \item Exactly what one row represents; every fact must match that grain.
    \item When history matters; implemented with valid\_from, valid\_to, is\_current.
    \item A business key has many historical rows; only one is current.
\end{enumerate}

\textbf{Week 6:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Partitioning prunes whole partitions; clustering sorts within them for finer pruning.
    \item High-selectivity filters on columns that are not the partition key.
    \item It precomputes query results at the cost of storage and refresh compute.
    \item One worker processing far more rows or time than its peers in a stage.
    \item Repeated dashboard queries; wasted on one-off ad-hoc scans.
\end{enumerate}

\textbf{Week 7:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item External tables read files in place; native tables use BigQuery-managed storage.
    \item \texttt{ST\_WITHIN} (or \texttt{ST\_CONTAINS} with arguments reversed).
    \item Source-cloud egress charges plus cross-region latency.
    \item BigQuery cannot reorganize data it does not store.
    \item Small or fast-changing data where ingestion overhead is unjustified.
\end{enumerate}

\textbf{Week 8:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item It applies BigQuery row/column security to files in GCS.
    \item Metadata over unstructured files such as PDFs and images.
    \item Linked datasets: subscribers query in place with no copy.
    \item Each party's raw rows and PII from the other.
    \item Central, auditable masking without maintaining per-role views.
\end{enumerate}

\textbf{Week 9:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item You pay only for job runtime instead of an idle cluster.
    \item Cheap but reclaimable --- use for workers and keep jobs idempotent.
    \item Decouples storage from compute so each scales (and bills) independently.
    \item Executor memory undersized for skewed partitions.
    \item Pending YARN memory/containers beyond current capacity.
\end{enumerate}

\textbf{Week 10:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item CDAP (Cask Data Application Platform).
    \item Interactive cleaning on samples before scaled production runs.
    \item Analysts building pipelines without writing Java or Python.
    \item Sources and sinks reachable only inside the VPC.
    \item Runtime arguments such as dates, paths, and table names.
\end{enumerate}

\textbf{Week 11:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item By reading the source database's replication/write-ahead log.
    \item Renaming a column; adding a nullable column is non-breaking.
    \item Rows with unknown or mismatched fields, unless schema updates are relaxed.
    \item The producer owns it; consumers version and agree to changes.
    \item How far the destination lags the source.
\end{enumerate}

\textbf{Week 12:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Retries re-execute tasks; side effects must be safely repeatable.
    \item The notification runs whether upstream tasks succeed or fail.
    \item An autoscaling GKE cluster.
    \item When the run depends on an external file's arrival, not a clock.
    \item Only small metadata --- never large payloads.
\end{enumerate}

\textbf{Week 13:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item It is forwarded to the dead-letter topic.
    \item The broker rejects publishes that violate the Avro/proto schema.
    \item Retry-induced duplicates; deduplicate on message IDs downstream.
    \item Very high, steady throughput with zonal (not regional) tolerance.
    \item Consumers are stuck or undersized and the backlog is growing.
\end{enumerate}

\textbf{Week 14:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item A PTransform is an operation; a ParDo is an element-wise user function.
    \item Logic bugs are caught cheaply before paying for runner deployment.
    \item Shuffle and state handling, enabling faster autoscaling.
    \item When you reuse a parameterized pipeline across teams or jobs.
    \item It adds workers based on backlog and CPU utilization.
\end{enumerate}

\textbf{Week 15:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Event-time progress; events older than it are considered late.
    \item State grows without bound, exhausting worker memory/disk and defeating autoscaling; timers fire as the watermark passes, so garbage collection frees each key's state after its TTL.
    \item \texttt{SEEN} stores already-emitted event IDs per key; \texttt{EXPIRY} fires at the TTL to clear that bag.
    \item Both inputs must share the same window assignment and join key, with outputs gated on watermark alignment; unmatched elements are buffered per window until allowed lateness expires.
    \item Streaming Engine deduplicates shuffle records and the Storage Write API commits offsets atomically; at-least-once plus downstream dedup is cheaper when sinks lack exactly-once support or duplicates are tolerable.
\end{enumerate}

\textbf{Week 16:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Metrics are defined once in LookML and reused by every explore.
    \item It activates warehouse data inside operational tools, not just reports.
    \item The same customer syncs as duplicate or mismatched records.
    \item Freshness versus API rate limits and per-call cost.
    \item Governance, row-level security, and embedded analytics at scale.
\end{enumerate}

\textbf{Week 17:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Logistic regression for binary classification.
    \item Automatic seasonality, holidays, and hyperparameter choices.
    \item Precision, recall, and ROC AUC --- never accuracy alone.
    \item No data movement; governance and security stay inside BigQuery.
    \item A wide gap between training and evaluation metrics.
\end{enumerate}

\textbf{Week 18:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item When data is tabular and custom architecture gains little.
    \item Model versions, lineage, and deployment targets.
    \item Online prediction serves the low-latency checkout flow.
    \item Which input features most drove a given prediction.
    \item Endpoints add managed scaling, authentication, and traffic splitting.
\end{enumerate}

\textbf{Week 19:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Keeps training and serving features consistent, preventing skew.
    \item Online serving --- low-latency feature lookups per request.
    \item A containerized, reusable step with a declared input/output contract.
    \item Drift plus data-quality checks passing an evaluation gate.
    \item Skew compares serving inputs to training; drift tracks input shift over time.
\end{enumerate}

\textbf{Week 20:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item When a pretrained API solves the task without a custom model.
    \item Retries with backoff, batching, and quota alerts.
    \item The Natural Language API.
    \item Store extracted text and labels in BigQuery with a search index.
    \item Per-call pricing scales directly with message volume.
\end{enumerate}

\textbf{Week 21:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Exfiltration by valid credentials to destinations outside the perimeter.
    \item No exportable key material exists to be leaked.
    \item CMEK lives in Cloud KMS; with CSEK you supply the key yourself.
    \item They let specified IPs or identities through the perimeter.
    \item A deny result proves the perimeter actually enforces.
\end{enumerate}

\textbf{Week 22:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Raw zones hold unprocessed landings; curated zones are governed and quality-checked.
    \item Structured metadata such as PII flags, owner, and quality scores.
    \item Nulls, ranges, freshness, and distribution anomalies.
    \item The domain owns the product; the center sets guardrails.
    \item It traces the broken column back to the upstream pipeline.
\end{enumerate}

\textbf{Week 23:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item A category of sensitive data, e.g.\ EMAIL\_ADDRESS, CREDIT\_CARD\_NUMBER.
    \item Tokenization --- reversible only by holders of the key.
    \item Detokenization then requires auditable KMS permissions.
    \item New or previously undetected PII appearing over time.
    \item Attempt to read raw values and verify the denial (negative test).
\end{enumerate}

\textbf{Week 24:}
\begin{enumerate}[nosep, leftmargin=1.5em]
    \item Remote state gives locking and survives local machines.
    \item Rows violating its condition fail the pipeline run.
    \item \texttt{terraform plan} plus Dataform compile/assert; apply only on merge.
    \item Short-lived federated tokens replace committed key files.
    \item \texttt{ref()} dependencies build the DAG that orders execution.
\end{enumerate}
